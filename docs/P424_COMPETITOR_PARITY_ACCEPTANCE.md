# P4.24 — Competitor parity acceptance protocol (R1)

This is an **execution protocol**, not a leaderboard. It inherits
[P4.23's 49-item capability audit](P423_COMPETITIVE_PRODUCT_GAP_REGISTER_20261105.md).
Do not claim superiority from README feature lists, tool counts, or mock-only tests.

## Frozen tasks

1. **Scientific report**: MRI fixture with inline punctuation, 70 native
   equations and 9 human-corrected EqEdit cases (private corpus; consent required).
2. **Preservation edit**: modify one cell and a single paragraph in an
   existing school form; prohibit unrelated margins/text changes.
3. **Institution template**: extract style from three authorized same-institution
   samples, approve a derived profile, create a novel document.
4. **Native export**: HWPX -> Windows Hancom PDF with explicit version/PID,
   page count, content identity and separately reviewed page images.
5. **Delivery**: authenticated user downloads exact revision-bound HWPX/PDF
   and reopens it independently.

## Benchmark fairness contract

For every product/task pair record:
- Repository URL, resolved commit, license and environment (OS, runtime,
  installed renderer, fonts, processor, memory and permissions).
- Frozen input content hashes and authorized private source references;
  no personally identifying content in the public log.
- Exact task prompt, tool calls, setup requirements, operator interventions,
  number of retries and failure reason.
- Wall-clock time from first tool invocation to verified user acquisition;
  exclude setup in a separate *explicitly labeled* measurement.
- Generated byte SHA-256, HWPX structural validity, native Hangul open status,
  page-by-page visual adjudication and manual corrections.
- Unsupported task or renderer absence = **UNSUPPORTED**, not zero seconds,
  PASS or silent substitution.
- Report *matched pairs* and sample size for latency/quality; do not rank
  unmatched hardware, document corpora or renderer versions.

## Promotion gates

- Unit tests verify control flow only; they do **not** establish native output.
- Structural quality != native rendering != visual judgment != consumer delivery.
- Never use untrusted renderer receipts as an independent source of truth;
  verify output bytes and source revision locally.
- Only human-approved style learning. Do not infer user style consent from
  an uploaded confidential template.
- Exact-head CI, native acceptance and source/Render equality must be reported
  separately. Keep main and Render unchanged while these gates are HOLD.

## R1 finding and immediate repair

Source readback found a regression in the P4.23 PDF wrapper: the earlier
receipt hardening removed the PDF header check. It was restored and covered
by a spoofed-payload test. The full PDF format and visual quality still
require separate validation; a magic header is only a low-level predicate.
