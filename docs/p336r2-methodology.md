# P3.36-R2 — Prospective Holdout, Presentation Roles, Dual Design Targets and Generation QA

P3.36-R2 converts the R1 empirical census into bounded product behavior. It does not treat public-office HWPX prevalence as a style winner.

## Data constitution
Batch 02 is sealed before byte intake. Whole source groups marked PROSPECTIVE_HOLDOUT remain untouched by feature tuning until the implementation freeze. DISCOVERY sources can inform compatibility work after blind-ID materialization. PDF-only controls inform presentation/design hypotheses only; they do not establish native HWPX semantics.

## Presentation-role layer
Native style/heading evidence remains authoritative as native structure. A separate presentation-role hypothesis layer may infer TITLE, HEADING, BODY, CAPTION and TABLE_TEXT from position, size contrast, bold contrast, alignment and structural container evidence. It deliberately ignores prose semantics and reports confidence/evidence rather than rewriting native truth.

## Dual design targets
- INSTITUTIONAL_COMPATIBILITY: compatibility-oriented defaults informed by observed Korean public-document conventions.
- POLISHED_REPORT: deliberate report-design defaults for requests such as “Word/PDF처럼 깔끔하고 세련되게”.
- EXPLICIT: user-supplied design tokens have the highest design authority compatible with native validity.

Observed prevalence cannot veto an explicit polished design target.

## Table-rich authoring
The existing P3.21 composer remains the writer. R2 adds table finishing through existing validated P3.23 primitives: page-break behavior, border treatment, and repeat-header semantics when the plan explicitly marks the first row as a header. No parallel table writer is introduced.

## Generated-document benchmark
Generated HWPX is evaluated through separate mechanical gates: native structure readability, table structural validity, long-table pagination, and presentation-hierarchy signal. The benchmark intentionally returns aesthetic_verdict = NOT_ADJUDICATED; visual controls and human design targets remain separate evidence.

## Holdout rule
The R1 holdout was structurally exposed before split sealing and cannot serve as a strict prospective validation set. Batch 02 prospective groups are the first clean holdout for R2 design-heuristic validation.
